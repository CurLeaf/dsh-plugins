# 手机产品面 · 全量对齐验收

视口 500×845（DPR 3）实测。判定只有三种：**闭环 / 已补完 / 无法补完**。
「有效命中」= 从控件边缘逐像素向外打点，遇连续 miss 即停得到的真实可点范围。

## 三、「无法补完 → 移除」这一桶：**空的**

把所有可交互入口点了一遍，**没有任何一个是"点了没反应"或"打不开"**：

- `+` 按钮一度被判 NO_OP，复测正常（左侧菜单弹出）
- `开启通知` DOM 不变，是因为走系统权限弹窗
- 4 个 28×28 图标位于 x>500，是桌面端控件，不是坏按钮

所以「彻底移除」没有执行对象——**没有半成品入口，只有尺寸偏小的入口，而尺寸已经全部补到物理上限。**

## 四、仍然差的 1~9px 为什么不再追

| 项 | 差多少 | 原因 | 再追的代价 |
|---|---|---|---|
| 输入区三图标 | 宽差 9（35 vs 44） | 邻居只隔 8px | 外扩必然重叠 → 点错，**比小更糟** |
| 输入区三图标 / 选择工作区 | 高差 1（43） | 所在行高 44/40 | 亚像素，再扩会侵入相邻行 |
| 对话 / 轨迹 | 宽差 1~10 | 左侧邻居占死、右侧紧邻 | 同上 |
| 更多会话视图 | 差 1 | 相邻挤压 | 同上 |
| 侧栏三图标 | 差 16 | 头部行高 32 + 两层裁切 | 必须改抽屉布局 |

要真正做到 44×44，唯一路径是**改布局**（输入行 44→52、抽屉头部 32→44 并重排间距）——那是产品决策，不是样式补丁。
