- **闭环**：在手机上完整可用
- **可补**：功能本身能跑，只是触控/尺寸/对比度不达标 → 由 `dsh-mobile-touch` 注入修复
- **待定**：需要产品决策才能判定（不是技术问题）

### 另有三个被布局卡死

侧栏头顶三个图标（搜索会话 / 视图选项 / 添加工作区）实测 **28×28，外扩后仍 28×28**。

原因不是选择器没匹配，而是被**两层父容器裁掉**：

```
button          bhn1Oq_searchButton   28×28  overflow visible
  └ div         bhn1Oq_search         28×28  overflow HIDDEN   ← 裁掉伪元素
      └ div     bhn1Oq_searchSlot     28×28
          └ div bhn1Oq_sectionHeader  480×32 overflow HIDDEN   ← 高度也不够
```

抽屉头部行高只有 32，图标 28，上下各 2px。**即使放出 overflow，最多也只到 32**，到不了 44。
现场试过「抬头部行高 + 放开 overflow」，实测仍 28×28（还有别的裁剪层），且继续硬试会牵连抽屉布局，已停手。

**结论：这三项要达标必须改抽屉头部布局（行高 32→44 并重排图标间距），属于布局改动，不是贴样式能解决的。**

### 关于那四个 ⚠

不是没做到，是**当前布局的物理上限**：

- 输入区那一行总高 44，按钮 28 → 上下各 8，有效高度天然是 43~44
- `+` / 盾牌 / GenUI 三个按钮**彼此只隔 8px**，各自最多向左右扩 4px，所以宽度到不了 44

要真正做到 44×44，唯一办法是**把输入区那行从 44 抬高到 52 并重排间距**——那是改布局，不是贴样式，属于产品决策。硬扩会让相邻按钮命中区重叠，反而更容易点错（这比尺寸小更糟）。

## 五、已完成（本轮）

`dsh-mobile-touch` 插件，纯 CSS，只在 `max-width: 640px` 生效：

1. 输入区三个图标 + 模型选择器 → 命中区 44
2. 顶部标签（对话/轨迹/更多会话视图）→ 四周 −10px
3. 侧栏头顶三个图标 → −8px
4. 菜单项 `[role=menuitem]/[role=option]` → min-height 44
5. 输入框占位符对比度 3.76 → 4.99
6. 模型选择器：`overflow: hidden` 使 `::after` 失效，改用加高盒子 + 负 margin

## 六、踩过的坑（供后续参考）

| 坑 | 表现 | 结论 |
|---|---|---|
| 客户端工厂没返回值 | 整页白屏：`invalid plugin, expect function or object with an "apply" method` | 工厂必须 `return { apply }` |
| `::placeholder` | 改颜色完全无效 | DSH 占位符是自绘 div（`*_placeholder`） |
| `overflow: hidden` | `::after` 被裁掉，外扩无效 | 该类按钮只能加高盒子 |
| 相邻按钮外扩过大 | 命中区互相重叠 → 点错 | 必须按实测间距分组，不能一刀切 |
| 哈希 class | `_iconButton_6nhg2_511` 会随构建变 | 一律用 `aria-label` 定位 |

## 七、自有产品面（设备控制台）对齐

控制台是我们自己的代码（`dsh-tunnel/src/console.mjs`），改的是源样式。

| 项 | 之前 | 现在 | 证据 |
|---|---|---|---|
| 登录密码框 | 340×36 | **340×46** | 实测 `getBoundingClientRect` |
| 登录按钮 | 340×34 | **340×46** | 同上 |

| 垂直布局 | `margin:12vh` | flex 居中 + `100dvh` | 登录块 20~825 |

### 本轮修掉的回归

给 `#login` 加 `display:flex` 时**盖掉了 `[hidden]` 的 `display:none`**，
登录成功后表单继续留在页面上（截图能看到登录框和设备面板同时出现）。

已改为 `#login:not([hidden]){display:flex}` + `#login[hidden]{display:none !important}`，
复验：`loginVisible=false / appVisible=true`。

**这个 bug 只有真看截图才会发现——尺寸和状态检查都是通过的。**

### 一个测量陷阱（记下来）

「复制」第一次测出 `28×28`、四个方向探针全返回 `null`——
不是样式没生效，是**元素在视口外**，`elementFromPoint` 对屏外坐标返回 null。
必须先 `scrollIntoView({block:'center'})` 再测，否则会误判成"没修好"。

同理，「复制」的 `::after` 一直是正常应用的（`content:""`、`inset:-9px`、父链全 visible）。

### 一个选择器陷阱

「对话 / 轨迹」**没有 aria-label**，只有 `role=tab`。按 aria-label 写规则会直接漏掉。
凡是找不到的，先 dump 一遍 `role` 和文案，别假定它有 aria-label。
