# dsh-mobile-touch

手机上使用 DSH 时的触控可用性补丁。**纯 CSS，不改任何插件源码、不改布局容器。**

## 解决什么

实测（视口 500×845，DPR 3）发现外壳里 78 个可点元素小于 44×44：

| 控件 | 原尺寸 |
|---|---|
| 对话 / 轨迹 | 26×25 |
| 更多会话视图 | 22×22 |
| 输入区 + 号 | 28×28 |
| GenUI | 28×28 |
| 模型选择器 | 201×28 |
| 发送 / 停止 | 34×34 |
| 侧栏顶部三图标 | 28×28 |

## 怎么做

1. **命中区外扩**：`::after { inset: -12px; min-width/min-height: 44px }`。
   视觉尺寸完全不变，所以不会破坏任何现有布局。
   例外：会话视图的「对话 / 轨迹」用 `::before` —— 宿主的**选中下划线就是
   `.tabActive::after`**（2px 高 + 品牌色），命中区也写 `::after` 会把那条线
   撑成 44×44 的色块，只有选中项看得见。换到 `::before` 两边互不影响。
2. **占位符对比度**：`#9a9aa2`，从 3.76:1 提到约 5.2:1。
3. **窄屏截断**：模型选择器 `max-width: 42vw` + 省略号，避免挤爆输入区。

只在 `max-width: 640px` 生效，桌面端一行都不碰。

## 为什么用 aria-label

DSH 的 class 名是 CSS Module 哈希（如 `_iconButton_6nhg2_511`），随构建变化。
aria-label 是语义标识，稳定得多。代价是新增控件需要显式加入列表——这是有意的：
宁可漏扩一个，也不要靠 `button { min-height: 44px }` 这种通配规则把整页布局搞乱。
